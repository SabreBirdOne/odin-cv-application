The guide used an array of objects, where each object could be one of the education entries. 
The add, edit and delete function that they present takes linear time.

Which sounds bad in a vacumn. But realistically, this array is used for a packing
list. I'm sure most people don't have *quite literally* billions of things in their 
packing list, so many things that would make array operations in JS physically slow.

The same can be said about a resume. Billions of schools passed and jobs experienced 
is impressive, but not realistic either. I find it acceptable to do things in linear time 
if the data size isn't enormous to begin with. So let's do array of "entry" objects.

The maintainability of code at this point is more valuable than pointless optimization.

I ran into a major implementation challenge with EduEntry, but I overcame it. 

As you know, eduData is managed by parent component EducationSection, an array of objects representing each entry. 
When EducationSection renders, it creates a list of <EduEntry> children components, each child getting one of the objects 
from eduData. 

However, EduEntry itself has 4 InputDivs, each responsible for 4 out of 5 of the columns of an entryData object. 

The flow has to go from: onChange in the inputDiv => setData(e.target.value) => ... => the parent's handler to update the eduData state variable.

I wrote InputDiv to only allow 1 argument, that being the new input value upon component change, but nowhere to supply *which* column 
to push this new input value to in the eduData state variable.

My solution is to use function currying! Function currying is basically: a function that constructs and returns another function. 
So I can construct 1-argument functions, one for each column of entryData.
